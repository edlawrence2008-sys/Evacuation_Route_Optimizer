**Changes — 2026-11-22 (route prototype removed; content generators fixed).**

- **Save-button fonts keep their aspect ratio.** Every scaled button on the Saves page now sets `keep_label_aspect`. `PauseButton3D.refresh_label_aspect()` counter-scales the Label3D by the inverse of the button's X/Y scale, so non-uniform 0.7/0.85 and 0.52/0.85 button transforms no longer stretch or squash the pixel font. Font sizes were retuned for the compact layout (header 18–20, actions 22, save rows 18–22), and runtime-created save rows enable the same setting.
- **Saves layout; brush placeables and per-cell palettes.** Reworked the authored Saves page so it uses the panel instead of stacking oversized buttons: compact scaled controls, six list rows, New Map / World Type in the top-left and Sort / Rename in the top-right, the thumbnail and details on the right, and two balanced bottom action columns. Long save names are shortened in the list (full name stays in details), and `saves_only` lifts Load when Save/Save As are hidden. Brushes now work with placeables: one copy per footprint column on the aimed surface, a footprint ghost instead of a single model, and brush breaking removes placeables inside the volume. Palette brushes and drags roll a fresh palette entry for **every affected cell** instead of one entry per shape, and both paths apply the shared Tool/Placement/Pattern filter; palette placeables are deduplicated per column.
- **Brush break mirrors the brush shape; save sorting; CTM colorbase groups.** Breaking with **Brushes** enabled now applies the Clear action to the same brush volume (Cuboid/Sphere/Cylinder/Surface/Cluster) instead of starting a rectangular drag. Removal is centred on the aimed block, while placement still uses the selected Merged/Attached/Inserted layer; the Clear tool carves the same centred volume. Placeables still break as placeables rather than carving the block behind them. The Saves panel gained a **Sort** button that cycles **Last Played** (default), **Date Created**, **Alphabetically** and **Date Modified**; `load_save()` stamps a new `last_played` manifest field, older manifests fall back to `modified`, and the chosen mode is persisted in `user://active_save.cfg`. `BlockMaterials.material_name()` now keeps `_colorbase` in **CTM** group ids, so `hardwood_cornered` and `hardwood_cornered_colorbase` no longer merge into one inventory group; autoblock `_colorbase_cNN` variants still share their base group.
- **Dynamic CTM for slabs/stairs; shape clicks assign the hotbar.** `NavGridMap._build_ctm_items()` now registers every `Auto_Connect_*` shape against one shared per-source atlas material and records its CTM base (`get_ctm_base`). `ChunkMesher._emit_ctm_item_mesh()` keeps the authored slab/stair triangles but computes per-face eight-neighbour masks and cell-space atlas UVs, so partial faces sample the matching slice of the tile and keep the border only on exposed edges. `_emit_ctm_block()` compares base groups instead of exact item ids, so a full block and its slab/stair variants connect. Clicking a shape in the block-group chooser now also assigns that exact item to the active hotbar slot through the same selection path as clicking the group cell; the color swatches keep their display-only behaviour. Verified: a lone `concrete_polished` top slab has mask 0, an east neighbour raises its top-face mask to 2, adjacent slabs/stairs show connected interiors with an outer frame, and choosing the slab changed hotbar slot 0 from `-1` to `755`.
- **Patterns replace dither; CTM slabs/stairs; color palettes.** Removed the dither controls entirely; the Pattern row (Solid/25/50/75/Checker/Inverse) now applies to both brushes and the normal stretch/drag. The connected-block generator emits top/bottom/side slab and normal/upside-down stair items for every CTM source; slabs/stairs use the interior CTM tile so they read as a continuous surface, while the full block keeps the dynamic per-face atlas (`_build_ctm_items` skips the static variants). Added `scripts/color_palette_db.gd`: it loads `textures/color_palettes/*.png` (16×1 strips). The block generator expands each `_colorbase` autoblock into full/slab/stair variants per palette color (`_cNN`), but does **not** bake a tinted texture: the mesh shares the base texture and the material's `albedo_color` supplies the tint. `BlockMaterials` strips `_colorbase_cNN` so all colors share one group, previews are tinted at 64×64, and the block-group panel filters to the selected color and shows the palette as colored squares at the bottom-right. Clicking a square switches the group's block/slab/stairs color; the rebuild is deferred because the clicked button is locked while its signal is emitting. CTM `_colorbase` sources do exist (`sheetmetal_clean_colorbase`), but palette expansion currently runs only through `BlockGenerator`; CTM color variants are still a gap.
- **Left build tab; Worldshaper brushes; quadrant stairs.** Added `Inventory/BuildTab` (`BuildTab.tscn` + `BuildPanel.gd`), a 246x336 left-side panel opposite the property tab that stays visible while the inventory is open. It drives `BuildController.set_build_settings()`: a **Brushes** toggle with **Cuboid** (W/H/L 1–32), **Sphere** (radius 1–10), **Cylinder** (radius/height 1–8), **Surface** (range 1–10) and **Cluster** (range 1–10); tools **Fill/Place/Overlay/Flatten/Replace/Clear**; placement **Merged/Attached/Inserted**; and a **Pattern** row (Solid, 25/50/75 %, checker/inverse). Brushes are one-click and deliberately disable stretch/drag. With brushes off, the **same Tool/Placement/Pattern** settings apply to the normal drag plane (Merged/Attached/Inserted choose the target/face-adjacent/opposite layer), with the same Pattern filter; dither was removed entirely. **Clear** applies to every brush shape and to the drag plane. The hover ghost is now always drawn when there is a target: blue when the click changes something, red for Clear, white when nothing would change (occupied fill cell, empty replace cell, missing selected block, player overlap). The Build tab's widgets are authored in `BuildTab.tscn` (not built at runtime), so the layout is editable. Fixed the `item_selected` callable arity error and the negative-face placement sign: Attached/Inserted now shift out/through the hit face in all six directions instead of reversing on negative faces. Stair placement still uses the clicked face quadrant: the taller back half goes to the clicked side, so floor/ceiling quadrants yaw the normal stair and wall left/right/top/bottom quadrants produce sideways/rolled stairs through the full 3D GridMap orientation. The normal `Auto_Stairs_*` item covers every case; the upside-down variants stay hidden.
- **CTM atlas UVs and directional item orientation fixed.** `ChunkMesher._emit_ctm_quad()` used `float(mask) / 16.0` for the atlas row, so every mask that was not a multiple of 16 sampled up to 15 source pixels into the next atlas row; 32x16 sources made the vertical bleed obvious. The 32x16 path also now matches the reference generator's layer model: q5 (the right 16x16 block) is alpha-composited **behind** q1-q4 instead of only replacing fully transparent pixels, so anti-aliased or partly transparent state pixels blend with the background. The CTM material now culls backfaces (`CULL_BACK`, matching the cube winding) instead of `CULL_DISABLED`, which had let the inside of a block's far side draw over its outer face, and it picks transparency from the atlas alpha: opaque for fully opaque sources (polished concrete, hardwood, whiteboard), alpha scissor for 0/255 cutouts, and alpha blending only for partial alpha (the classroom window glass). Both tile components are now integer indices. Separately, `_emit_item_mesh()` read `GridMap.get_cell_item_basis()`, which is always identity because the runtime GridMap mirror is dropped (packed sections are the source of truth), so placed stairs and other directional items rendered unrotated even though the ghost used the stored orientation. It now reads `get_block_orientation(cell)` and converts it with `get_orientation_basis()`.
- **Every content generator is now an `EditorScript` tool.** `ConnectedBlockGenerator` changed from a `RefCounted` utility to `@tool extends EditorScript` with a `_run()` entry point, so it works with **File → Run** like the block and foliage generators. The voxel-item editor wrapper was renamed `voxel_item_generator_tool.gd` → `voxel_item_generator_editor.gd` to make it clear that `voxel_item_generator.gd` is the shared `RefCounted` core used by runtime icon lookups, not the runnable tool. The plugin now reaches the editor base control through the `EditorInterface` singleton instead of `get_editor_interface()`. All five scripts pass `--check-only`; the plugin still loads with `Content Generators: ready (Project > Tools).` World generators remain runtime generators and are excluded.
- **Content generators actually run.** The `addons/content_generators` plugin is enabled again in `project.godot` (a stale missing `McpBridge` autoload was removed) and its menu callbacks now call **static** entry points instead of instantiating `EditorScript`s: `BlockGenerator.generate_all()`, `ConnectedBlockGenerator.generate_runtime()`, `FoliageSceneGenerator.generate_all()` and `VoxelItemGenerator.generate_all()`. `BlockGenerator` was refactored from instance helpers to statics and returns `{textures, variants, synced}`; the plugin reports those counts and surfaces errors as `push_error`/`push_warning`. The plugin logs `Content Generators: ready (Project > Tools).` on load. Verified from the static entry points: 52 texture groups / 263 variant slots / 321 MeshLibrary items, four `Auto_Connect_*` items, nine foliage scenes. Regenerating also produced `Auto_sheetmetal_green` and its slab/stair variants.
- **Route prototype removed.** Supersedes the 2026-11-21 route-point entry below: the authored-route code, route-via A*, `Member` route adoption, `route_*` console commands, route tests and `PackedVector3Array` export were deleted, and the route investigation is parked.

**Changes — 2026-11-21 (procgen foundation: packed 3D sections, generator contract).**

- **Route-point placeables; content generator menu.** Hand-authored routes are now built from individual **Evac Route Point** placeables (`sim_evac_route_point.tscn`). Points no longer connect automatically: in build mode click point A then point B to link A -> B, hold Shift for a bidirectional link, click A again to clear its link, and right-click/break to delete a point. Each point has a stable `point_id`/`next_id`, direction arrows and a `->` / `<->` / `END` label; fully bidirectional chains also expose a reverse route. Agents enter at the nearest point within its capture radius instead of walking back to the route start. The `EvacRoutePath` container remains for scripted routes and also supports nearest-point entry. Console `route_*` commands create point placeables and `route_add` links the new point to the previous one. Separately, the editor-side block, connected-block, foliage and voxel-icon generators are exposed through **Project > Tools** by the `addons/content_generators` plugin; the plugin is re-enabled in `project.godot` and a stale missing `McpBridge` autoload was removed. `docs/CONTENT_GENERATORS.md` records inputs, outputs and troubleshooting. Tests: `route_via_test.gd` (17) and `route_optimizer_test.tscn` (28); full suite **576 assertions across fourteen harnesses**.
- **Extras generator tab removed.** The temporary **Extras -> Generators** page was deleted at the owner's request (`_ensure_generators_ui`, `main_menu._open_generator`, `PauseMenu.open_generator`). World generators remain selectable in **New Map -> World Settings** through `WorldGeneratorRegistry`. Stale docs that described the tab were corrected.
- **World-generator registry; Extras tab removed.** `WorldGeneratorRegistry` is now the single list of UI-exposed generators (Flat Platform, Heightmap Terrain, plus future entries). `SaveManager` accepts any registered generator instead of only `heightmap_v1`; Flat Platform creates through the same recipe path (verified 4 chunks / 80 cells / `flat_v1`). The World Type dropdown, caption, confirmation and save descriptor all use the registry. Adding a generator is one registry entry plus its generator class.
- **Jigsaw infrastructure study.** Added `docs/JIGSAW_STRUCTURES.md`: a feasibility study for deterministic module/socket assembly and an in-game template capture/socket editor. **Investigation only — no structure system was added.** It covers the existing `WorldRecipe.generate_structures` hook, a cached global layout, chunk-border emission, nav reachability, baked-versus-instance saves, risks and phased effort.
- **Foliage distance LOD.** Generated crossed-card foliage now uses three stages instead of one hard cutoff: both cards and the primary shadow near; the **primary card switches to a single fixed-Y billboard at mid distance** (the secondary card fades out and its shadow is disabled); the billboard fades out at the far distance. This removes the thin edge-on silhouette and halves the card count at range. Fades use 30–40 m margins, so a crowd thins out gradually instead of every whole plant popping at one cutoff. Grass keeps the preset far range (80/120/150 m), but **trees, palms and bushes extend to 300 m at High** (240 Medium / 160 Low) with a mid billboard at half that, so distant trees no longer disappear at 150 m. Runtime check: tree near `Sprite3D_A` crossed + shadow; tree at 200 m fixed-Y billboard, no override, shadow off, far 300/mid 150. Grass at 90 m fixed-Y billboard, far 150/mid 75.
- **Coarse far LOD and chunk-order pass.** Far terrain now uses genuinely larger voxels: LOD1 is a **4×4** coarse column and LOD2 is **8×8**, with heights snapped up to 4- and 8-block bands. Coarse columns are cached per chunk/step (terrain edits invalidate the chunk and border neighbours), and a short edge skirt covers LOD transitions so the coarser chunk cannot leave a vertical gap. The mesher now builds the **nearest full-detail chunk first**, then up to **four cached far-LOD chunks per frame** under a separate 2.5 ms budget. The outer ring previously lagged because every chunk shared the one-full-chunk-per-frame cap; that is fixed. The black contour bands visible at distance are **not missing LOD chunks** — wireframe/unshaded checks show complete geometry; they are unlit vertical faces under the map's near-black ambient light.
- **Simulation Defaults, water and mesh-priority pass.** Runtime exports were already **per save** (`save.json` → `runtime_exports`); new saves start from `user://export_defaults.json`. Settings → Gameplay → **Simulation Defaults** now names that page explicitly and adds **Use Current Session**, which captures every live export at once (global limits/flags, Agent/Member overrides, Random Populate and optimizer configuration), not only the five global fields. Water profiling on a 40×40, 1,600–2,000-cell pool reduced water processing from **2.58 → 0.59 ms/frame** and the worst frame from **38 → 10.8 ms**: the hydrostatic pass is now incremental with a 2 ms budget (30 → 3.9 ms/call), ambient surface droplets sample a few cells instead of scanning the whole pool (was 17 ms/call), splash-ripple meshes update at 10 Hz with a 12-ripple cap (1.05 → 0.11 ms/frame), and crest meshes update at 10 Hz. Chunk meshing now rebuilds the **nearest dirty chunk first** instead of dictionary insertion order reversed (which had effectively prioritized the farthest streamed chunks), so near chunks and their LOD transitions appear before far detail. Tests remain **531 assertions** across twelve harnesses.
- **Large-world performance pass.** Five measured hot paths were fixed on the empty Large (384×384, no NPCs) scenario:
  - **Sparse fast import.** `VoxelSectionStore.import_column()` rejected sparse sections because it required `palette_size >= 1`; sparse sections serialize a zero palette. 110/335 generated chunks fell back to an 8.7 ms per-cell decode. All chunks now import directly.
  - **One-pass snapshots.** `get_chunk_cells_and_items()` returns the cells and item ids from the packed sections in one pass. `_create_chunk_snapshot` fell from **3.99 ms to ~2.0 ms/chunk**, and interior padded-border lookups are skipped (a chunk cannot contain cells outside its own min/max Y).
  - **Streamer footprint clamp.** `_rebuild_desired()` uses the recipe's `get_footprint_chunk_rect()`, so a 66-chunk load radius around a 24×24-chunk Large world builds **576 desired chunks instead of ~17,000**. The view-crossing rebuild fell from ~12–17 ms to sub-millisecond.
  - **One chunk per frame.** Generated worlds set `ChunkMesher.max_builds_per_frame = 1`; a 10–12 ms chunk can no longer pair with a second and double the frame.
  - **Navigation.** Initial `build_chunk_navigation()` now memoizes item reads for the build and only adds/removes the chunk's cells plus a border weight/connection refresh: **~134 ms → ~25 ms per nav chunk**. The nav pump is skipped entirely when there are no NPCs, spawners or exits, so exploring an empty generated world keeps **180 FPS and 0 nav points** instead of paying ~5 s of 25 ms nav hitches.
  - **Settings + spawn.** `new_blank_map()` re-applies the saved `PerformanceSettings` after the scene reload (new maps previously silently used Medium defaults), freezes the player during world generation, and re-places it on the finished surface before the save. Measured fill frames fell from **~39 ms to ~17.4 ms (57 FPS)**, with creation running at **55–95 FPS** instead of ~20–40, and a Large creation around **17 s** including the save. Tests: `heightmap_generator_test.gd` 36/36 adds a cross-chunk nav path; `chunk_store_test.gd` 38/38 adds sparse fast-import and parallel-item coverage. Total **531 assertions**.
- **Simulation panel teardown.** `_update_status()` now returns when the panel is outside the tree, and `_exit_tree()` disconnects the panel from `SimRecorder.recording_state_changed`, `RuntimeExports.runtime_exports_applied` and the `GlobalData` spawning/NPC signals. Loading a different save while a recording auto-finalized could emit `recording_state_changed` after the old inventory panel had detached, so its status refresh called `get_tree()` on null.
- **Terrain step slabs.** `HeightmapTerrainGenerator` now places a **bottom slab** (`step_slab_item = 46`, `step_slabs_enabled = true`) in the air cell at `top + 1` on the low side of every one-block terrain step. Each full riser becomes two half-block steps, using the existing bottom-slab nav profile (`slab_path_cost`, half-height nav point), so the hard one-block slope guarantee and A\* rules are unchanged. The chunk border is sampled once per generated chunk (`chunk_size + 2` lattice) so cross-chunk steps also get a slab. `get_params`/`apply_params` carry the new fields. The height-field LOD still rounds a slab column to a full block at distance. A loaded save can be retrofitted with `NavGridMap.add_step_slabs()` / the console `/slabs` command, which is idempotent and only fills empty `top + 1` cells. Headless coverage: `heightmap_generator_test.gd` 33/33, including default-on, slab-at-`top + 1` on every lower step side, and no slab on flat/high columns. MCP Large (384×384): **452,794 cells including 10,426 step slabs**; 576 full meshes and 576 collision bodies with LOD off, 197/338/41 LOD0/1/2 and 197 collision bodies with `/lod on`, both 180 FPS after the fill.
- **Packed 3D section store.** `VoxelSectionStore` replaces the per-cell `_chunk_cells` dictionary in `NavGridMap`. Columns own sparse 16×16×16 sections; each section auto-selects a sorted sparse encoding (8 B/cell, < 96 cells) or a palette + 1/2/4/8-bit dense encoding (~2 B/cell for floors). Sections above 256 palette entries stay sparse, so the two encodings cannot convert-loop. Measured floor fixture: **3.28 bytes/cell for the section index**, down from roughly 1 KB/cell for the old dictionary index.
- **Chunk collision, runtime mirror dropped (P0c).** `ChunkMesher` builds one `StaticBody3D` + `ConcavePolygonShape3D` per chunk from the committed `ArrayMesh`, on the grid's collision layer/mask, tagged with `meta("nav_grid", grid)`. When chunk meshing is enabled (the default), `NavGridMap._ready` seeds the packed store from the scene GridMap, calls `GridMap.clear()`, and leaves GridMap empty at runtime. `BuildController._is_grid_collider()` accepts chunk bodies as grid hits, and all game-side cell reads moved to `get_block_item()` / `get_block_orientation()` / `get_used_block_cells()`. Live check: 66 chunks, 66 collision bodies, 14,679 cells in 76,664 bytes (~5.2 B/cell), **0 GridMap cells**, player standing at y = 1.9; placing a block moved a downward ray hit from y=1 to y=2 and removing it returned to y=1. With meshing disabled (headless tests, legacy scenes), GridMap keeps its cells as the collision source and the store mirrors them.
- **Chunk format v2.** `NavGridMap.CHUNK_DATA_VERSION` is now 2: a ZSTD-compressed section blob with a deterministic section-Y sort. Version-1 flat 5-int cells still load and upgrade on the next save. `ChunkFileStore` is unchanged.
- **Heightmap terrain generator (P2).** `HeightmapTerrainGenerator` (`heightmap_v1`) generates a bounded, deterministic footprint with value-noise FBM + ridge. Heights are built on an 8-block coarse lattice, projected with the exact 4-neighbour min-plus transform (adjacent nodes differ by at most the spacing), then bilinearly interpolated and floored, giving a hard **≤1 block per cell** slope that matches the A* stair steps. Each column emits 3 blocks for collision. Wired through `WorldRecipe`. Measured 256×256 (256 chunks, 196,608 cells): **839.7 ms generation** (3.28 ms/chunk), **34,163 B** compressed blobs, **477,172 B** store (2.43 B/cell); 64×64 collision (16 chunks) costs **0.63 ms/build**, 10.0 ms total. 64-chunk generated distance still needs threading and LOD.
- **Procgen New Map in both menus (P2 integration).** The shared Saves page (main-menu `saves_only` overlay + pause menu) now opens a **World Settings** dialog from the World Type button: Blank Platform or Heightmap Terrain, size 128/256/384, seed (`0` = random). `SaveManager.new_blank_map()` accepts a procgen descriptor, resets the scene (`NavGridMap.reset_world()` + `ChunkStreamer.reset_streaming()`) so the starter platform cannot survive, applies a `WorldRecipe`, waits for the origin chunk, and places the player above the generated surface. `save.json` pins `generator`, `generator_version`, `seed`, `size` and `options`; loading applies the recipe and regenerates missing chunks (a version mismatch warns). The legacy protected-floor fill is disabled when a recipe is set, and save details show `Heightmap terrain · seed <n> · <size>`. MCP smoke: 64 chunks / 49,152 cells / 64 collision bodies / **0 GridMap cells**; loading restored the recipe, metadata and player.
- **LOD opt-in and seam fixes (follow-up).** LOD is now **off by default** for every save (`ChunkStreamer.lod_override = -1`); `/lod on` enables it and `/lod off` restores full detail, so existing and authored saves look unchanged. The bands were widened to full ≤8 chunks and 2× ≤14 (4× beyond). Fixed three heightfield defects found on Large worlds: the top face was emitted from `y + 1` and floated one block above the terrain; the +X/+Z side faces sat one coarse cell outside their column, leaving black cracks; and chunk-edge sides never sampled the adjacent chunk, so seams opened at chunk borders (`_build_lod_border_columns` now reads the neighbour's first/last coarse row/column). Wireframe checks with LOD fully off, and an unshaded-material check, confirm the remaining dark contour is the heightmap's guaranteed 1-block terracing: the vertical faces that do not face the sun sit in shadow and the map ambient is nearly black (`sky_contribution = 0.01`), so they render as dark lines. It is a lighting/art issue, not a missing or displaced mesh. With LOD on, the Large world measured **197 full / 338 half / 41 quarter** and **197 collision bodies**; with LOD off it meshes 576 full chunks and 576 collision bodies, both at 180 FPS after the fill. Renderer/engine review: [`docs/RENDERER_AND_ENGINE.md`](RENDERER_AND_ENGINE.md) — stay on Godot 4.7 `mobile`; the profiled bottleneck is GDScript CPU, and neither `Zylann/godot_voxel` nor `rimworld3d` justifies a switch.
- **Render LOD and far-collision gating (P1).** *(Superseded by the opt-in bullet above; the original bands were full ≤5 and 2× ≤12.)* `ChunkMesher` added three distance bands: full greedy mesh + trimesh collision within 5 chunks (baked AO within 3, greedy merging beyond), 2× heightfield to 12 chunks, and 4× heightfield beyond, with no collision outside LOD0. `ChunkStreamer` sets the mesh radius to `max(mesh_radius, load_radius)` for recipes so a bounded footprint is fully meshed; this fixes the missing outer ring on Large worlds. `set_view_center()` now queues only new/LOD-changed chunks instead of every populated chunk on each 16-block crossing. The streamer skips chunks outside a bounded recipe footprint, defers A* to the budgeted nav pump during bulk generation (one chunk/frame), and raises the generation budget to 9 ms / 4 chunks. `NavGridMap.load_chunk()` imports the compressed v2 blob directly into sections when no nav rebuild is needed, removing the per-cell decode/insert (profiled ~7.5 ms/chunk). Creation pre-fills the whole footprint and waits for the initial LOD pass before saving. Measured Large (384×384, 576 chunks, 442,368 cells): **576/576 meshed**, one-time creation **~17 s** (down from 25 s / 11 FPS), **180 FPS** after the fill.
- **Generator contract.** `WorldGenerator` defines a pure `sample_column` / `generate_column` / `generate_structures` API and a stable id/version/params triple. `WorldRecipe` composes a base generator, ordered overlays and a scenario stage, emits v2 chunk data, and exposes `get_manifest()` for save and run pinning. `FlatGenerator` reproduces the shipped 80-cell platform through the new interface.
- **Streamer hook.** `ChunkStreamer.world_recipe` selects the generator; a bounded recipe owns its footprint and an empty result means empty (no flat fallback). `ChunkMesher` and `MapRenderer` consume `get_chunk_cell_list()` instead of materialising a dictionary per chunk.
- **Tests.** `procgen_test.gd` 50/50, `chunk_store_test.gd` 38/38 and `heightmap_generator_test.gd` 36/36 (encodings, palette overflow, hysteresis, negative Y, determinism, ZSTD, malformed blobs, v1 migration, recipe → grid, disk round-trip, index memory, dropped GridMap mirror, collision body and physics ray, compressed fast import including sparse sections, cells+items, slope guarantee, slab placement and `/slabs` retrofit, params round-trip, generation/collision cost, cross-chunk navigation, LOD levels and far-collision gating, streamer generation). Total **531 assertions** across twelve harnesses; all existing optimizer, demo and recording suites still pass.

**Changes — 2026-11-20 (per-save exports, recording control, Load State handoff).**

- **Per-save runtime exports.** `RuntimeExports` captures the player-changeable runtime state into `save.json` under `runtime_exports`: `global_unit_cap`, `global_spawn_quota`, `rng_seed`, evacuation mode, record-on-start, `GlobalData.agent_overrides`, Random Populate settings and the optimizer configuration. Loading a save applies them after `reset_spawning`; old saves fall back to the current export defaults. Vector/Color values are tagged and revived so JSON round-trips `sprite_offset`.
- **Export defaults in Settings.** Settings → Gameplay now has **Export Defaults**, a scrollable page with the global limits/flags and the full Member export list. **Save Defaults** writes `user://export_defaults.json`; **Reset All Defaults** clears it. New blank maps apply these defaults. The inventory Agents panel now resets to the export defaults rather than hard-coded scene values.
- **Recording control.** The Simulation panel adds **Start/Stop Recording** for a capture that does not follow Start; **Record On Start** keeps the existing automatic mode. A manual recording survives a later Start. `SimRecorder` auto-finalizes when every configured quota has been spawned and no member is alive; unlimited-quota runs stay open.
- **Load State continuation recording.** Loading a demo state now creates a new demo whose `recording.jsonl` copies the source prefix through the load tick (run header, spawns, ticks, routes, evacuations, disruptions) and then records live continuation. The new run header records `resumed_from`/`resumed_at`, and the combined summary includes the pre-load evacuation history.
- **Load State handoff.** The Load State confirmation and loaded popup are now clamped, scrollable windows. After loading, the pause menu closes, simulation time is frozen with `Engine.time_scale = 0`, the inventory opens, and time resumes only when the inventory is closed.
- **Tests.** `recording_control_test.tscn` 31/31; total **236 assertions** across eight harnesses.

**Changes — 2026-11-20 (late-agent diagnosis, editable demos, readability).**

- **Late agents diagnosed and fixed.** Parsed 332-agent recordings: the 100–130 s tail was the 0.64–0.88 m/s desired-speed tail on 58–83 m routes (75–113 s travel), not a crowd-following anomaly. The optimizer averaged that tail into faster cohorts, predicted the cohort early and could assign a longer route. `CohortBuilder` now keeps per-agent speeds and `ExitCostAnalyzer` builds one arrival per agent (`distance / speed`), so the makespan sees the slowest walker. Exit cooldowns now survive successful paths; when every exit is on cooldown the agent waits for the earliest expiry; navigation refreshes re-path to the **same** exit instead of re-choosing. The run summary/F4 panel list the top-5 latest agents with speed, pre-movement, distance, stuck time and route changes.
- **Editable demos.** Demo Player **Load State** imports the current playback tick into the live map while keeping spawners alive. It restores recorded serials, positions, exits, desired speeds, pre-movement remainder, route/contact counters and spawn times; replays earlier evacuation events into the manager; restores exit admission totals; and restores each spawner's spawned/section counts and interval phase. Spawners keep spawning from those counts, then the optimizer can **Run once**. It is a best-effort restore, not a bit-exact replay: path geometry, queue order, contact state and already-evacuated agent nodes are not recreated.
- **Comparer readability/verification.** A **Final Summary** table (total/average/P95/max time, peak density, peak contact, deaths) and a **Verdict** line compare runs directly; the detailed differences stay collapsed. The optimizer scenario line now includes method/mode.

**Changes — 2026-11-15 (crowd model).**

- **Social Force Model replaces the ad-hoc crowd push.** `CrowdManager` (now 609 lines) runs one pair sweep per 30 Hz tick: Helbing & Molnár psychological repulsion with anisotropy, Helbing/Farkas/Vicsek body contact and tangential friction, and a normal dashpot. Every pair is evaluated once and both agents are updated in the same pass, so the old 20-neighbour cap and scan-order asymmetry are gone. See `docs/SIMULATION_MODEL.md` for equations and provenance.
- **Kinematic locomotion for scale.** `Member` defaults to `use_kinematic_movement = true`: a single downward ground probe replaces `move_and_slide()` against the voxel trimesh, with ledge refusal, a one-voxel step-up limit, and gravity integrated in the movement layer. This is the change that let 600 agents hold 47-91 FPS where the physics path managed roughly 10. `use_physics_contact = true` restores engine collision for comparison.
- **Wall repulsion from the voxel grid.** `NavGridMap.get_wall_acceleration()` samples eight directions out to 0.8 m with the 2000 N / 0.08 m constants, cached per 0.2 m position and body-radius bucket (65,536-entry cap, invalidated on nav change).
- **Determinism and a simulation clock.** `GlobalData` gains `sim_time`/`sim_now()`, `rng_seed`, `claim_agent_serial()`, and `reset_determinism()`. Agents seed a private RNG from `(rng_seed, agent_serial)`, deadlock right-of-way uses the serial instead of the instance ID, and every reported time uses the physics clock rather than wall time.
- **Pre-movement and exit choice are now behavioural models.** Agents wait a lognormal delay (mean 6 s, σ 0.7, max 45 s, toggleable) and choose exits with a logit utility over baked flow-field route length, queue density, line of sight, and a stable familiarity term, sampled with Gumbel noise. Duplicate `EvacPoint` group entries are deduplicated.
- **Lanes are emergent.** `lane_offset_strength` and `max_extra_lane_offset` now default to `0`; anisotropy and friction produce lanes, counter-flow separation, and exit arching without per-agent offsets.
- **Density and instrumentation are real.** `get_density_count()` / `get_density_per_m2()` no longer cap the query and only count agents on the same floor (vertical band 0.9 m); `CrowdManager.get_stats()` reports `agents`, `pairs`, `solve_usec`, and `cells`; the snapshot adds `pre_movement_wait`, `peak_contact_force`, and `contact_overlaps`; `EvacuationManager` aggregates `average_pre_movement` and `peak_contact_force`.
- **Spawner and exit fixes.** `NPCSpawner` places each body before `add_child`, so an exit near the world origin no longer fires a false `body_entered` for every new agent. The `sim_evac_point` trigger radius dropped from 3 m to 1 m so agents are removed near the marker rather than far from it.
- **Presets and test map.** The High preset and `AGENT_CAPS` now include 600. `Maps/test.tscn` congestion overrides were softened to `2.0 / 0.5 / 0.35`, matching the script defaults.
- **One-block steps are traversable again.** Navigation has always connected one-block step-up edges, but the kinematic probe allowed only 0.65 m and its ray started below a 1 m step, so agents could not follow those routes. The probe now climbs `kinematic_step_height = 1.05 m` (full blocks, slabs, panels, stairs) while still refusing two-block faces, and `kinematic_snap_down_height = 0.65 m` keeps 1 m drops as short falls. The SFM wall force also no longer repels single-block steps: it stopped agents ~0.4 m short of a step they were meant to climb. A three-step staircase test climbed 0.75 → 1.75 → 2.75 → 3.75 m, and a two-block wall still blocked.

Spawned birds face their flight direction, fade in/out of sampled dense cloud points, rest for a random 7–18 s, and leave on their own. Full design and tuning are in `docs/FALSE_BOIDS.md`.
- **Pause Spawning and a real Reset.** The Simulation tab has a `Pause Spawning` toggle that keeps the run, counters, quotas, and live crowd intact while spawners stop emitting; Start clears the pause. - **Contact-force distribution instead of a lone peak.** `CrowdManager` now records the global peak and its time, mean force, overall and non-zero-only percentiles, non-zero fraction, agent-seconds above 0.5/1/2/3 kN, and a 0.5 s force–time series. `EvacuationManager` exposes them as `contact_force_stats` and resets them per run. Congestion A* weights are applied in bounded 64-cell batches every 0.1 s instead of synchronously. - **Foliage sway.** `scripts/foliage_sway.gd` is attached to every generated foliage scene root (and the generator now adds it to new ones). On `_ready` it swaps each non-billboard `Sprite3D` card to `shaders/foliage_sway.gdshader`, a spatial shader that bends the top of the card in world space with a two-sine wind, while keeping the base planted and preserving alpha-scissor cutouts, nearest filtering, double-sided rendering, and lighting. **All cards and all plants that share a texture share one ShaderMaterial**, and the shader derives the phase from the plant's world origin, so a map full of foliage does not create per-plant materials. Crossed planes on one plant bend together; different plants still move out of phase. Billboard cards are left alone so their orientation is not broken. Grass textures opt into `flip_backface_normals` and `stable_grass_shading`: the stabilised path forces the shading normal to world-up and uses that same up direction for the view/SSS term, so grass brightness depends on the sun rather than which crossed card faces the camera. Bushes and trees keep the default card normals. The shader also has a custom `light()` pass with a **green-only subsurface term**: green-dominant albedo pixels get a translucency/wrap response (`sss_strength`, `sss_sigma`, `sss_power`, `sss_scale`, green thresholds), while non-green pixels keep a normal Lambert response. - **Water system.** `WaterSystem` uses one float depth per cell, measured from a per-cell floor; a full block is `MAX_HEIGHT = 16` units, but waterlogged partial blocks hold less. Air/water cells have base 0 / capacity 16; bottom slabs leave the top half (`base 8`), top slabs leave the bottom half, bottom panels leave 13/16, top panels cap the cell, and stairs/side variants use the slab rule. Water therefore no longer fills the whole cell and clips through those blocks. The four runtime items are volume shortcuts (Surface/Full 16, Slab 8, Panel 1). Water falls into waterloggable cells below, falling columns are pulled down in the same tick, and losing a cell wakes the layer above so a stranded 1-high film can drain. It spreads a one-unit film into empty neighbours and equalizes wet cells by water surface (`base + depth`) so a slab cell and a normal cell settle level. A periodic hydrostatic pass (0.5 s) only connects cells in the same Y layer, grows the top layer into empty neighbours, and solves a common surface by bisection while respecting each cell's capacity, so large placements do not keep a 16→1 gradient and the pass cannot level through walls via a higher connection. Tanks equalize (one full block in a 2-cell tank becomes 8/8; 24 units in a 3-cell tank with a bottom slab become 2.67/10.67/10.67 at a common surface) and overflow stacks upward; placing a slab into a full water cell pushes the displaced volume up. Surface and full are the same capacity volume; the exposed top renders 0.9 and picks as Surface, covered/stacked renders at the top and picks as Full, and a top-mounted partial suppresses the water top face to avoid z-fighting. Water below the chunk's lowest block minus 5 (the same kill margin as `Member`) is destroyed. The renderer builds one custom mesh per 16×16 chunk from exposed faces only, starts the water at the partial block's top (a bottom slab's water is visible from 0.5 to 1.0 instead of clipping through it), hides internal water faces, and uses a simple lit depth-fade + foam shader (no refraction or waves); its shallow foam uses a per-1/16 m-texel hash, so water noise is on the voxel-pixel grid. Partial water always renders as a horizontal layer; there is no wall-panel rotation. A separate unshaded mesh draws a depth-scaled 1–5-texel scrolling sea-foam border sampled from `textures/particles/sea_foam.png`, with corner bands trimmed so adjacent banks meet without overlapping. A matching corner patch from `sea_foam_corner.png` sits 0.6 mm above each L-corner to bridge the texture ends seamlessly without z-fighting. Surface waves are a real 2D wave-equation simulation: samples propagate, reflect off water borders, and interfere; moving player/NPC actors inject brushes sized from their collision shapes (or `wake_brush_radius` metadata), and the wake is a filled, dithered palette field rendered as 1×1 texels, using exact palette entries with no bilinear colour blending. The `wake_style` export switches between the soft gray-blue palette and a more saturated, shorter-lived Vivid palette. Splashes use a 32-sprite `splash_small` pool with a runtime 90°-rotated frame atlas, inject a wave brush, and add a square white-texel ripple; particle count/size, wake brush, and ripple radius scale strongly with hitbox size, peak fall height, and vertical impact speed. Exposed 1-unit water sitting on a full block also emits small water particles. The bright wall-edge foam keeps a one-texel outer strip and adds a denser four-texel inner band that scrolls inland using white or light-blue texels. Waterloggability is cached and no-op height writes are skipped, so still water costs nothing per tick.

- **Stairs, body rotation and facing tools.** Stairs were turned 90° to the player's left because `stair_front_axis` assumed +X while the generated stair's low/front step points +Z; it is now `Vector3.BACK` and stairs face the player. The player's `CharacterBody3D` yaw now follows the camera (mouse X rotates the body, not the head), so the character's facing matches the view. `ui_rotate` (Q) quarter-turns the stair placement, and the aimed block face gets a five-zone overlay (inset centre square + four edge trapezoids) with the crosshair's zone highlighted. The overlay's axes are fixed per face (not camera-relative), so it stays static on the voxel while the zone mapping still reads correctly from the face's outside. **The zone quads are now indexed by the same `FACE_ZONE_*` ids the hit test returns**; the previous quad order was centre/bottom/right/top/left while the classifier returned centre/right/left/top/bottom, which highlighted a different edge than the one under the crosshair. All six faces × five zones were checked live (30/30).
- **Upside-down stairs, vertical slabs and unified slab/stair inventory.** The block generator now also emits `Auto_Slab_Side_<texture>` (a vertical half-slab occupying the +X half, rotated by GridMap orientation) and `Auto_Stairs_UpsideDown_<texture>` (same two-step mesh with the half-step on the top). The MeshLibrary grew from 162 to **245 items**, preserving every old ID. The inventory lists one **Slab** entry per material: bottom and side variants stay in the library but are hidden, and the old top/bottom badge is hidden. Slab placement resolves the variant and orientation from the clicked face zone: floor middle → bottom slab; wall middle → side slab hugging that wall; wall top/bottom → top/bottom slab; left/right wall quads → side slabs oriented to that edge; floor edge quads → side slabs oriented to that edge. Stairs are unified the same way: one **Stairs** entry per material, with the upside-down variant hidden. On a wall, the top quad resolves to the upside-down stair; every other wall quad and all floor/ceiling quads use the normal stair. The slab mapping was verified live for all six faces × five zones (30/30), and actual placements confirmed floor-middle → bottom slab, wall-middle → side slab (orientation 16 for a +Z wall), wall-top → top slab, and wall-left/right → side slabs (orientations 10/0). Stair placement was verified on a +Z wall and floor: wall-top → upside-down, wall-bottom/center/left/right → normal, all five floor quads → normal; a legacy upside-down hotbar item also resolves to normal on a wall-bottom hit.
- **Placeable properties moved into the new Property tab.** The right-side `Inventory/Property_tab` now hosts the adjustable rows; the old `Inventory/VarScroll` container was removed. (Superseded 2026-11-09: the tab is now a general item inspector with a preview, title, placeholder block stats, description, and exports, shown for blocks as well as placeables.)
- **Navigation favors stairs, then slabs.** `NavGridMap` now classifies block items by surface. Nav points for bottom slabs and normal stairs sit on the half-height surface, so agents no longer see them as a 0.5 m climb and stop hopping unnecessarily. A* point weights now include `stair_path_cost = 0.75`, `slab_path_cost = 0.9`, and `full_block_path_cost = 1.0` (all exported), so an equal-length stair or slab route beats a full-block route. Live tests: a 3-cell stair route (cost 2.25) and a 3-cell bottom-slab route (2.7) were both chosen over the equal-length full-block route (3.0). Changing a full block to a bottom slab moves the same A* point from y = 9.0 to 8.5.
- **Build hold audio.** `player.tscn` now carries `build_hold_loop`, `build_hold_increment`, `build_hold_cancel`, and `build_rotate`. The loop starts only once a press passes `build_hold_delay` and becomes a drag/hold, so a single click is silent; it fades in over 0.12 s and fades out over 0.18 s instead of clicking on/off. The increment cue fires when the ghost selection's **bounding size** changes (not only when the cell count changes): growing plays a slightly higher pitch, shrinking a clearly lower pitch. Increment cues use a voice pool (4 preallocated, up to 16 on demand) so rapid size changes no longer restart and cut off the previous cue. `build_hold_cancel` plays when a hold is interrupted (inventory/build-mode toggle, death, movement disabled) and `build_rotate` plays on `ui_rotate` (Q). The nodes are resolved by name or stream path so older/renamed scenes still work, with a runtime fallback if the scene has no matching node.
- **Empty-handed boot.** The hotbar starts with all nine slots empty, so the player begins empty-handed; the inventory no longer contains a Hand group or Empty Hand tile (removed 2026-11-09).
- **Container transfer protocol.** `Hotbar` exposes `container_get_slot`, `container_set_slot` (returns the replaced item), `container_take_slot`, and `container_slot_count`. Slot controls opt in with `item_container` + `container_index` metadata. Since 2026-11-09 item movement uses Godot drag-and-drop rather than a cursor overlay (see the 2026-11-09 entry); future chests/crates can implement the same four methods and reuse the slot drop handling.
- **Mantle interruption fix.** `Player._cancel_mantle()` now clears `is_on_ledge` and `mantle_timer` when noclip toggles, movement is disabled (inventory/console), or the player dies. Previously the stale mantle timer and upward launch velocity could re-enter the mantle path after noclip/collision was restored, throwing the player up or into geometry.
- **`allow_yielding` is now an export.** `Member.allow_yielding` (Crowd Dynamics, default `true`) gates the deterministic right-of-way yield. Disabling it makes agents keep their line and rely on collision instead of backing off; it is automatically exposed in the Agents panel like the other Member exports.
